|---|---|

| 市场 | **A 股优先**（任务书要求，T+1/涨跌停/印花税这些规则也最考验引擎）。美股留成数据源插件，P4 前不做 |

| 数据 | baostock 为主（有停牌标志、ST 标志、历史指数成分、退市股），akshare 当备份和交叉校验；Parquet 快照 + SHA256 清单 |
| 引擎 | **两种模式共用同一个"规则内核"**：向量化模式用来扫参，事件驱动模式出权威结果并驱动 Win 模拟。两种模式要过一致性测试 |
| 防未来函数 | 三道机械化防线：① 只给策略 Point-in-Time 视图（结构上拿不到 t 之后的数据）；② **截断/扰动测试**（改动 t 之后的数据，t 及以前的信号必须一字不差）；③ AST 静态扫描 |
| 防粉饰 | 实验登记簿（每次回测都追加记录，不能删）+ **锁箱期**（2024-07-01 起的数据在最终报告前不许碰）+ Deflated Sharpe / PBO 过拟合度量 |
| ML | LightGBM 截面排序模型，滚动重训，Purged K-Fold + Embargo 防泄漏。**不做 RL，不用 LLM 生成信号**，理由见 §5.4 |
| Win 模拟 | 一个 supervisor 进程管多个 worker 进程（每个 worker 用 Windows Job Object 硬限内存 512MB），SQLite 存检查点，FastAPI 提供只读面板，用户级计划任务实现登录自启 |
| GPU | **默认不用**。日频截面数据量小、分支多，CPU 多核更合适。不为了"用上 GPU"硬塞，报告里如实写 |

## 1. 旧代码评估：留什么、推什么、为什么

评估依据：通读 `main` @ `a8047c3` 的 8378 行代码，加上 review/05 专家评审。

### 1.1 结构性问题（决定推倒重来的原因）

1. **面向美股实盘设计，没有 A 股市场规则。** 全仓库找不到 T+1、涨跌停、印花税、100 股一手、停牌、集合竞价的建模。这些东西补不上去：成交规则得放在引擎核心，旧代码是后来套上去的。
2. **回测是同一根 bar 内成交。** `core/backtest.py` 用当根 bar 的价格算信号，又用同一根 bar 的价格成交，这是典型的未来函数。没有成交延迟，也没有成交量约束。
3. **回测和实盘是两套代码。** `core/engine.py`（实盘循环）和 `core/backtest.py` 各自实现一遍状态管理，所以出了 `avg_cost=0` 这种"回测里看不见、实盘里静默失效"的 bug。新架构要求**研究、回测、模拟走同一个内核**（借鉴 nautilus_trader 的思路）。
4. **风控用已实现盈亏。** 浮亏触发不了日亏限额（review 遗留 bug 2）。根源在于没有逐 bar 盯市的统一账户模型。
5. **防未来函数靠人眼。** 没有任何机械化检测。`core/alpha_factors.py:129` 的 `shift(-horizon)` 作为标签本身没问题，但整个仓库没有机制保证它只出现在标签里、不进特征。
6. **数据不可复现。** 每次运行都现拉 yfinance，没有快照也没有校验和，同一次回测重跑不出来。
7. **策略库求广不求深。** PPO、Transformer、LLM alpha、Stacking 都有，但没有一个经过样本外检验，测试也只覆盖 happy path。

### 1.2 逐模块处置

| 旧模块 | 处置 | 理由 |
|---|---|---|
| `core/engine.py`、`main.py` | **丢弃** | 美股实盘循环，单策略 bug，avg_cost bug。新的事件引擎重写 |
| `interfaces/*`（ibkr/okx/binance/schwab/ths） | **丢弃** | 本项目禁止接实盘下单，不能把下单通道留在新代码里 |
| `strategies/options.py`、`leverage.py`、`contracts.py` | **丢弃** | 期权、杠杆、合约不在 A 股现货模拟范围内 |
| `core/backtest.py`、`paper_trading/*` | **丢弃** | 同 bar 成交，没有 A 股规则，模拟系统是玩具级 |
| `core/rl_agent.py`（PPO）、`transformer_model.py` | **丢弃** | 日频样本只有几千个，在这么少的数据上做 RL / Transformer，过拟合几乎必然，也没有样本外证据。torch 依赖还会单独吃掉 2GB 以上，项目目录 4GB 上限装不下 |
| `core/llm_alpha.py` | **丢弃** | LLM 的训练语料包含 2008–2024 的真实市场结果，拿它在历史上生成信号就是**用了未来信息**，这一点无法消除 |

| `core/alpha101.py` | **当参考** | 公式本身是公开文献（Kakushadze 2016）。v6 挑约 20 个和 A 股日频相关的重写，每个都要过 PIT 测试 |
| `core/factor_analysis.py` | **当参考** | IC / IR / 分层收益的概念正确。v6 重写，加上换手、衰减、行业中性化 |
| `core/walkforward.py` | **当参考** | 滚动窗口的思路对，但缺 purge / embargo，选参也只看 IS Sharpe。v6 重写 |
| `core/portfolio_optimizer.py`（HRP） | **当参考** | HRP 可以作为一种组合方式。v6 自己实现，与旧实现的结果做对照测试 |
| `core/pairs_enhanced.py` | **当参考** | 协整 + z-score 的框架可以借鉴。v6 限定在同行业内配对，并加上形成期 / 交易期严格分离 |
| `core/risk.py` | **当参考** | 规则清单可以参考。v6 改成基于盯市净值，挂在引擎每个 bar 的钩子上 |
| `core/regime_detector.py`（HMM） | **丢弃（报告侧）** | 报告的"市场情形"用**事先固定的日期区间**划分，不用事后拟合的 HMM。事后拟合本身就带了后视偏差 |
| `core/meta_labeling.py` | 暂不纳入 | P2 之后，如果 ML 策略在样本外站得住，再评估要不要加 |

| `.github/workflows/ci.yml`、`.pre-commit-config.yaml` | **改写** | 思路保留，内容按新结构重写 |
| 仓库里提交了 `__pycache__/*.pyc` | **修正** | v6 的 `.gitignore` 会排除 |

**结论：** 旧代码中**零行**直接进入 v6，6 个模块作为算法参考。两个遗留 bug 不去修，它们所在的代码整个被替换掉。v6 的单测会专门覆盖这两类问题：持仓成本必须真实计算，日亏限额必须用盯市净值。

## 2. 对标的业界标杆（借鉴什么、不借鉴什么）

| 标杆 | 借鉴的设计思想 | 不照搬的部分 |
|---|---|---|
| **nautilus_trader** | 回测和实盘（这里是模拟）**共用同一套事件内核**；时钟抽象（回测时钟 / 实时时钟 / 加速时钟可以互换）；订单状态机 | 它是 Rust 核心 + 通用多资产框架，太重；我们只需要 A 股现货 |
| **vectorbt** | 向量化回测：把信号矩阵（时间 × 标的）一次性转成成交和净值，用 numba 加速，适合大规模扫参 | 它默认在信号当根 bar 成交，也没有 A 股约束；我们强制下一根 bar 成交，并把涨跌停 / T+1 掩码放进向量化路径 |
| **qlib** | 数据层 Point-in-Time 设计；"特征 → 模型 → 截面打分 → 组合 → 执行"的流水线分层；Alpha158 风格的特征工程；滚动重训 | 它的数据格式和 workflow 系统太重，也依赖它自己的数据服务 |
| **backtrader** | Strategy 接口的易用性（`on_bar` 风格），Analyzer 插件化 | 它是逐 bar Python 循环，扫参慢；Broker 模型过于简单 |
| **López de Prado《Advances in Financial ML》** | Purged K-Fold + Embargo、Deflated Sharpe Ratio、PBO（CSCV）、实验登记 | — |
| **Almgren–Chriss / 平方根冲击律** | 冲击成本 ∝ σ·√(Q/ADV) | — |

所有核心代码自己写。外部只依赖基础库（numpy / pandas / numba / pyarrow / lightgbm / scipy / statsmodels / fastapi / psutil），不打包任何回测框架成品。

## 4. 关键模块设计

### 4.1 数据管道（data/）

- **数据源：** baostock 的 `query_history_k_data_plus` 提供日线 / 5 分钟线 OHLCV、成交额、`tradestatus`（停牌）、`isST`、`preclose`；`query_hs300_stocks(date)` / `query_zz500_stocks(date)` 提供**历史时点**的指数成分，用来消除幸存者偏差；`query_all_stock(day)` 能拿到含退市股的全量列表。akshare 作为备份源，并在抽样日期上做价格交叉校验（偏差超过阈值就报警）。
  - P1 第一项任务就是**实测上面每个接口的可用性和起始日期**，实测结果写回本文档。接口能力以实测为准，不以我的记忆为准。
- **宇宙：** 每个月末取当时的沪深 300 + 中证 500 成分（中证 800），**不用今天的成分回看过去**。
- **复权：** 存不复权价 + 复权因子，按需计算后复权（用于收益计算）和不复权（用于涨跌停判断和手数计算）。**涨跌停必须用不复权价判断**，这是常见错误点。
- **缺失处理：** 停牌日保留行，标记 `tradable=False`，价格前值填充只用于估值，不用于成交；上市未满 N 日的新股排除；明显异常的 bar（high < low 等）记录到隔离表，不静默修正。
- **快照：** `build_snapshot.py --asof 2026-09-30` 生成 `data/snapshots/<id>/`，内容是按年分区的 Parquet（zstd 压缩、float32）加 `manifest.json`（每个文件的 SHA256、行数、来源接口、拉取时间、代码版本）。回测入口只接受 snapshot_id，引擎启动时校验哈希，不一致就拒绝运行。**同一 snapshot + 同一配置 + 同一 git sha → 字节级一致的结果**，这一点有测试保证。
- **体积预算：** 中证 800 的历史并集约 2000 只股票 × 2005–2026 日线，估算 Parquet 约 300–500MB；5 分钟线只取 2019 年以后的子集。P1 实测后定稿。

### 4.2 Point-in-Time 与防未来函数（core/pit.py, lint/）

三道防线，全部机械化执行：

1. **结构防线：** 策略的 `on_bar(ctx)` 只能拿到 `ctx.view`，这是一个 PITView 对象，内部持有游标 t，所有访问方法都只返回 `≤ t` 的切片，底层数组不对策略暴露。标签（未来收益）只能通过 `ml/labels.py` 生成，而且只在训练窗口内使用，训练窗口末端按标签期限做 purge。
2. **截断 / 扰动测试（核心）：** 对每个策略、每个因子自动执行：任取时点 t，把 t 之后的数据①截掉，②替换成随机噪声，分别重跑。**t 及以前产生的所有信号和目标权重必须与原始运行逐位相等。** 测试矩阵覆盖所有已注册的策略和因子，进 CI，有一个不过就红。这比代码审查可靠：不管未来函数藏在 pandas 的哪个角落（`rolling(center=True)`、`bfill`、全样本 `rank` / 标准化），只要真的用了未来数据，这个测试就会失败。
3. **静态防线：** AST 扫描 `shift(-n)`、`bfill`、`center=True`、全样本 `fit_transform` 等危险模式，白名单仅限 `ml/labels.py`。这一道是辅助，主要作用是让问题更早暴露。

此外还要求**成交时序**：在 t 根 bar 收盘时产生的信号，最早在 t+1 成交（日频是次日集合竞价或次日 VWAP，可配置）。引擎层强制执行，策略改不了。

### 4.3 市场规则与成本（market/）—— 引擎正确性的核心

| 规则 | 建模 |
|---|---|
| 涨跌停 | 主板 ±10%，ST ±5%，创业板 2020-08-24 起 ±20%，科创板 ±20%，北交所 ±30%；新股上市首日等特殊情况单独处理或排除。用不复权 `preclose` 计算并按交易所规则取整到分 |
| 不可成交 | 停牌不能成交；涨停价封板（一字板 / 收盘在涨停且没有打开过的情况按排队模型处理）买不进，跌停同理卖不出 |
| T+1 | 当日买入的股票当日不能卖，持仓分成可卖 / 冻结两部分 |
| 手数 | 买入 100 股整数倍；卖出允许零股一次性清掉 |
| 佣金 | 默认万 2.5，单笔最低 5 元（可配） |
| 印花税 | **按历史时点表计算**：2008-04-24 前 0.3%（双边）、2008-04-24 起 0.1%（双边）、2008-09-19 起 0.1%（仅卖方）、2023-08-28 起 0.05%（仅卖方）。具体日期和税率在 P1 由 Bob 查证官方公告并附出处，Cen 复核 |
| 过户费 | 按历史规则（沪市早期按股数，2015 年后统一按成交额），同样查证后入表 |
| 滑点 | 固定基点（默认 5bp）+ 冲击成本 |
| 冲击成本 | 平方根律：`impact = k · σ_daily · sqrt(Q / ADV20)`，k 默认 0.1，做敏感性分析 |
| 成交量约束 | 单笔不超过当根 bar 成交量的 10%（可配），超出部分留到下一根 bar 或撤单 |
| 成交延迟 | 信号 t 收盘产生 → t+1 执行（日频）；5 分钟模式下延迟 1 根 bar |

这些规则只在 `market/` 里实现**一次**，向量化引擎和事件引擎都调用同一份。

### 4.4 双模式引擎（engine/）

- **事件引擎（权威）：** 按 `Clock`（回测时钟 / 加速时钟）推进 bar。每个 bar 的处理顺序固定：撮合挂单 → 更新盯市 → 风控检查 → 调用策略 → 提交新订单。账户模型统一维护持仓成本、可卖数量、现金和冻结资金，盯市净值每个 bar 更新。**Win 模拟系统直接复用这个引擎**，只把时钟换成加速时钟。
- **向量化引擎（扫参）：** 输入目标权重矩阵 W[t, i]，用 numba 循环逐日执行"目标权重 → 下一日成交"。涨跌停、停牌、T+1、手数、成本全部用掩码和同一套费率函数实现。速度预期比事件引擎快 50–200 倍（P2 实测）。
- **一致性测试：** 同一策略、同一数据，两种引擎的净值曲线逐日偏差必须小于 1bp（或者完全一致；具体允许范围在 P2 根据撮合模型的差异定下来）。不一致就说明某一边错了。
- **撮合模型（matching.py）：**
  - 集合竞价：日频模式下以 open 作为竞价成交价，成交量上限取当日成交量的一个比例；如果 open 就在涨跌停价上，进入排队模型。
  - 涨跌停排队：bar 级数据看不到队列，所以采用保守概率模型：涨停价买单的成交比例 = f(当日在涨停价上的成交量 / 封单估计)，**默认取保守值（一字板成交 0%）**，并对这个参数做敏感性分析。这是模型假设，报告里会写明。

### 4.5 策略接口与策略库（strategy/）

```python
class Strategy(Protocol):
    name: str
    def on_init(self, ctx: InitContext) -> None: ...          # 声明所需字段、预热期长度
    def on_bar(self, ctx: BarContext) -> TargetWeights | None:  # 只能读 ctx.view (PIT)
        ...
    def on_fill(self, fill: Fill) -> None: ...                # 可选
```

- 策略**只输出目标权重**，不直接下单。下单、约束、风控由框架负责。这就是"新策略只需实现约定方法、不用改引擎"的接口。
- 配置里每个策略有 `enabled` 开关；`combo.py` 按配置权重（或风险平价）把多个策略的目标权重合成一个组合。

| # | 策略 | 要点 |
|---|---|---|
| ① | 时序动量 / 趋势 | 指数 ETF 层面和个股层面各一版；用波动率目标控制仓位；回看期做敏感性分析 |
| ② | 截面多因子 | 价值、动量（12-1）、短期反转、低波、流动性、质量（如果有 PIT 财务数据）；做行业 + 市值中性化，按 IC 加权或等权合成 |
| ③ | 均值回归 / 配对 | 短期反转（截面），以及同行业协整配对：形成期 / 交易期严格分离，z-score 进出场，加止损 |
| ④ | ML：LightGBM 排序 | 约 60–150 个价量特征，标签是未来 5 / 20 日超额收益的截面排名；每 3 个月滚动重训，Purged K-Fold + Embargo；固定随机种子 |

### 4.6 组合与风控（portfolio/, risk/）

- **组合构建：** 目标权重 → 约束投影：单票上限（默认 5%）、行业上限（默认 20%，行业分类用申万一级或证监会分类）、换手上限、相关性约束（组合内两两相关系数高于阈值时降低合并权重，或用 HRP 分配）。实现上用 scipy 求解，加 clip-redistribute 兜底，不引入 cvxpy 这类重依赖。
- **风控（事件引擎每个 bar 调用，基于盯市净值）：**
  - 单日亏损限额（默认净值的 -3%），触发后当日只允许减仓；
  - 最大回撤熔断（默认 -20%），触发后清仓或降到配置的风险等级，冷却 N 日；
  - 交易前检查：资金、可卖数量、涨跌停、停牌、手数。
- **已知数据限制：** 免费渠道的行业分类可能只有当前值，没有历史时点值。如果 P1 证实确实如此，报告会写明"行业约束使用的是当前行业分类，存在轻微的后视偏差"。

### 4.7 评估体系（research/）

- **Walk-forward：** 训练窗口 3 年（可配），测试窗口 6 个月，滚动步长 6 个月；训练和测试之间按标签期限 purge，外加 embargo。**报告只拼接测试窗口的结果作为样本外成绩。**
- **锁箱期（Lockbox）：** **2024-07-01 至快照截止日**，这段数据在 P4 最终报告前不参与任何研发和调参。最终配置先 commit（commit hash 作为预登记），然后只跑一次，结果原样进报告，不管好坏。
- **市场情形：** 事先固定区间，不做事后选择：2008 金融危机（2008-01~2008-11）、2009 反弹、2014-07~2015-06 牛市、2015-06~2016-01 股灾、2018 熊市、2019 反弹、2020-01~03 疫情冲击、2021 结构市、2022 熊市、2024-01 小盘股流动性危机（2024 年初这一段落在锁箱期之前，可用）。
- **敏感性：** 参数敏感性（每个关键参数 ±50% 网格，画热力图）、成本敏感性（成本 × 0.5 / 1 / 2 / 3）、冲击系数和排队成交率的敏感性。
- **过拟合度量：** 实验登记簿记录所有试过的配置数 N，据此计算 **Deflated Sharpe Ratio** 和 **PBO（CSCV）**，结果写进报告。
- **指标：** 年化收益、年化波动、夏普、索提诺、最大回撤及持续期、Calmar、胜率、盈亏比、年化换手、成本占毛收益的比例、容量估计（按 ADV 参与率换算的资金规模上限）。
- **基准：** 沪深 300 全收益（如果拿不到全收益指数就用价格指数，并在报告里注明）、中证 800 宇宙等权（每月再平衡，扣同样的成本）、买入持有。
- **"真实场景收益率"的口径：** 默认初始资金 100 万元，全成本，样本外拼接 + 锁箱期，分别报告。同时给出 1000 万和 1 亿资金下冲击成本上升后的收益衰减。**收益是负的就写负的。**

### 4.8 实验登记簿（registry/）—— 诚实条款的工程化

每次运行回测或扫参，自动向 `registry/runs.jsonl` 追加一条记录：git sha、snapshot_id、配置哈希、随机种子、时间、核心指标。这个文件只追加，进 git。报告生成器从登记簿读取"总试验次数"，用于 DSR，并列出"被淘汰的配置"统计。挑样本和偷偷多试，在这个机制下都会留下痕迹。

## 5. 技术选型及理由

| 选型 | 理由 | 放弃的备选 |
|---|---|---|
| **Python 3.12 + uv** | Win 已装 uv；uv 能在 Mac 和 Win 上装同一个 Python 版本、共用一份 lock，可复现性最好。Mac 现在的 Anaconda 是 3.9，太老，不用 | conda（Win 上没装，环境体积大） |
| **numpy + pandas + numba** | numba 编译向量化路径的热循环，速度接近 C | polars（团队熟悉度低；pandas 配合 float32 列式存储已经能满足 512MB 约束） |
| **pyarrow / Parquet + zstd** | 列式、压缩率高、跨平台字节稳定，方便做哈希 | HDF5（跨平台锁文件问题）、CSV（体积大、精度会漂移） |
| **LightGBM（CPU）** | 截面表格数据上的业界主流方法，速度快，可解释（特征重要度），可复现（deterministic=True + 固定 seed） | PPO / Transformer（见 §1.2，另外 torch 太大）；XGBoost（差别不大） |
| **scipy / statsmodels** | 组合优化、协整检验 | cvxpy（依赖重，Win 上编译有风险） |
| **FastAPI + 原生 HTML + SSE** | 只读面板，浏览器打开就能用，内存占用小 | Streamlit / Dash（常驻内存大，容易碰到 512MB 上限） |
| **SQLite（WAL）** | 存模拟检查点和成交流水，单文件、崩溃安全 | Redis / Postgres（多一个常驻服务） |
| **pytest + hypothesis** | 用 property-based 测试验证规则内核的不变量（现金守恒、持仓非负、T+1 等） | — |

### 5.4 明确不做的东西及原因

- **RL（PPO 等）：** 日频 A 股的有效样本量太小，非平稳性又强，RL 在这种条件下很难得到可信的样本外结果。任务书允许"树模型或 RL 至少一种"，选树模型。
- **LLM 生成信号 / 情绪：** 历史回测里的 LLM 本身"知道"后来发生了什么，这是无法消除的未来信息。Win 上的 qwen 只作为**开发辅助**（例如给 Bob 的代码做第二意见、起草报告的文字部分），不进交易回路，也不进回测。
- **实盘接口：** 硬约束禁止。v6 代码里不会出现任何券商下单 SDK。

## 6. Win 24h 加速模拟系统（sim/）

```
计划任务 "Quant6Supervisor"（用户级，登录时触发，失败后自动重启）
   └─ supervisor.py  (≤150MB)
        ├─ worker × N  (每个都是事件引擎 + AcceleratedClock，Job Object 硬限 512MB)
        │     每个 worker 跑一组 (策略组合, 参数, 回放区间)；每 K 根 bar 写一次 SQLite 检查点
        ├─ janitor     定时统计 D:\quant6\saves 的体积，超过 1.8GB 就把旧的回放结果滚动归档成 zstd，超过 2GB 删最旧的一批
        ├─ healthz     心跳文件 + HTTP /healthz（检查各 worker 心跳、内存、磁盘）
        └─ web.py      FastAPI :8790，只读：运行列表、净值曲线、持仓、成交、日志尾部、资源占用
```

- **全真回放：** 逐 bar 回放快照里的真实历史数据（日线，或 5 分钟线），每个交易日按 `集合竞价 → 连续交易 bar 序列 → 收盘` 推进，撮合、涨跌停、停牌、T+1 全部走 §4.3 / §4.4 的同一内核。
- **加速：** `AcceleratedClock(seconds_per_trading_day=N)` 可配；N=0 表示尽快跑。
- **并行：** Ultra 7 265F 有 20 核，默认开 12 个 worker（给老板的日常使用留余量），每个 worker 单线程。12 × 512MB ≈ 6GB，在 32GB 内存里很宽裕。
- **断点续跑：** 检查点里有账户状态、挂单、策略状态（策略必须实现 `state_dict / load_state_dict`，否则不能接入模拟）、回放游标、RNG 状态。worker 重启后从最近的检查点继续，**续跑结果和不中断运行的结果逐位一致**，这一点有测试保证。
- **崩溃自恢复：** supervisor 检测到 worker 退出或心跳超时就拉起新 worker，带指数退避；supervisor 自己由计划任务的"失败后重启"兜底。
- **日志轮转：** RotatingFileHandler，单文件 20MB × 5 份，计入 2GB 预算。
- **资源硬上限：**
  - RSS：Windows 上用 Job Object 的 `JOB_OBJECT_LIMIT_PROCESS_MEMORY` 做硬限，超限会被系统终止，然后由 supervisor 记录并重启；另外 worker 内部用 psutil 做软限（超过 450MB 主动降低缓存）。核查命令会输出每个进程的 `peak_wset`。
  - 磁盘：项目目录 `D:\quant6\`（代码 + venv + 数据快照）预算 ≤4GB；`D:\quant6\saves\` ≤2GB，由 janitor 执行。不装 torch 是能达标的关键之一，venv 估计约 600MB。
- **安全边界：** 只在 `D:\quant6\` 内读写；只新建一个以 `Quant6` 为前缀的用户级计划任务；**不碰电源 / 引导 / 驱动，不碰现有计划任务（包括 OllamaServe）和老板的任何脚本，不重启机器**。部署脚本写 `install.ps1` / `uninstall.ps1`，可以完整撤销。
- **开放问题（P3 需要 Adam 确认）：** 用户级"登录时"触发的任务，只有在用户登录后才会运行。如果要求"无人登录也运行"，需要用"无论是否登录都运行"模式并保存账户密码，这属于改动老板机器的账户配置，**需要先得到授权**。默认方案用登录触发。

## 7. 已知局限（先写清楚，不藏）

1. **不是逐 tick：** 免费渠道拿不到 A 股的历史逐笔或十档快照。模拟精度是 **bar 级**（日线，以及近几年的 5 分钟线）。集合竞价和涨跌停排队是基于 bar 数据的**模型**，不是真实队列重放。接口按 tick 粒度设计，以后有了 tick 数据源可以接入。
2. **PIT 财务数据有限：** 免费财务数据的发布日期可能不准确。质量因子会用"报告期 + 法定披露截止日"这个保守滞后，避免使用未来信息。
3. **行业分类可能不是历史时点值：** 见 §4.6。
4. **不保证盈利：** 框架负责的是诚实地测量，测出来是什么就报告什么。A 股中证 800 宇宙上的日频多因子策略，在扣除全部成本后，样本外超额可能很小，也可能为负，报告会如实呈现。
5. **GPU 默认闲置：** 理由见 §0。如果 P2 实测 LightGBM 训练成为瓶颈，再评估 GPU 版本。
