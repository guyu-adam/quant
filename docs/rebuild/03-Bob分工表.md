# P0-3 给 Bob 的分工表

> 本表定义：派什么、按什么顺序派、每份活怎么验收。任务编号和 `02-任务拆分清单.md` 对应。

## 1. 派单机制

- **派单命令：** `bash ~/.hermes/scripts/bob.sh "$(cat <任务卡路径>)"`
- **任务卡：** 每个任务一张卡，放在 `~/Projects/agents/bob/tasks/<ID>.md`，由 Cen 写。卡片固定包含：目标、输入、精确规格（函数签名 / 字段 / 文件路径）、禁止事项、**验收命令**、交付格式。Bob 只需读卡，不需要理解整体架构。
- **工作区隔离：** Bob 在 `~/Projects/agents/bob/quant-v6`（`rewrite/v6` 的 git worktree）里，每个任务开一个分支 `bob/<ID>`，**只 commit 不 push**。Cen 审查后 cherry-pick 或 merge 到 `rewrite/v6` 再 push。这样 Bob 的错误不会直接进入主线。
- **交付格式（Bob 回复必须包含）：** ① 改动文件列表（绝对路径）；② 验收命令及**真实完整输出**；③ 未完成项或卡点。缺任何一项直接打回。
- **打回规则：** 同一任务最多打回 2 次，第 3 次由 Cen 接手，并在阶段汇报里记录。
- **通用禁止事项（写进每张卡）：** 不许改 `src/q6/core|engine|market/rules_cn.py|research/walkforward.py`（Cen 负责的模块）；不许 push；不许接任何券商 SDK；不许为了让测试通过去修改测试的断言；不许编造数据源的返回值（mock 必须来自真实录制）；在 Win 上只能在 `D:\quant6\` 内操作。

## 3. Cen 的审查清单（每份 Bob 产出都过一遍）

1. **亲自复跑验收命令**，不看自报告。
2. 看 diff：有没有越界改动 Cen 负责的模块、改测试断言、硬编码数据。
3. 涉及数据或因子的产出：确认截断测试覆盖到了这份产出。
4. 有没有引入新依赖？引入了的话，检查体积和 Win 兼容性。
5. 通过后合并、push，在任务清单上打勾，并记录到阶段汇报。
