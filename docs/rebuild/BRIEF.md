## 二、交付物（三件，缺一不可）

### 交付物 1：前沿水平的量化交易框架（本地可跑）

"前沿水平"的**可验收定义**（用工程事实说话，不用形容词）：

1. **回测引擎**：事件驱动 + 向量化双模式；**无未来函数**（有机械化检测，不是靠人眼）
2. **现实成本建模**：手续费、印花税、滑点、冲击成本、涨跌停/停牌不可成交、成交延迟
3. **组合与风控**：仓位管理、行业/个股权重上限、单日亏损限额、最大回撤熔断、相关性约束
4. **策略库**：至少覆盖 ① 时序动量/趋势 ② 截面因子（多因子打分）③ 均值回归/配对 ④ 机器学习（树模型或 RL 至少一种）；**每个策略必须能独立开关与组合**
5. **数据管道**：真实行情接入（A 股优先，可选美股）、复权、缺失处理、**数据快照可复现**（同一份数据能重建同一次回测）
6. **评估体系**：严格 **walk-forward / 样本外**切分、参数敏感性、成本敏感性、**多市场情形覆盖**（须含 2008 / 2015 / 2018 / 2020 / 2022 这类熊市与震荡段）
7. **工程化**：可测（单测覆盖核心路径）、可复现（固定随机种子 + 锁定依赖）、有 CI 式一键验证脚本、**配置与密钥分离**

> 选型自由：允许对标并借鉴业界开源标杆（如 vectorbt / nautilus_trader / qlib / backtrader 的设计思想）。**借鉴思想可以，直接打包别人的成品交付不行。**

### 交付物 2：Win 上的 24 小时加速模拟交易系统

运行环境（已实测）：**Win 台式机 `192.168.0.103`，Ultra 7 265F / 32GB / RTX 5060 Ti 16G / C 828G + D 1423G 空闲**，免密 `ssh win`。

要求：

1. **全真交易模拟**：真实历史行情**逐 tick/逐 bar 重放**，含集合竞价、涨跌停、停牌、T+1、撮合排队；**不是"用收盘价乘一乘"的那种玩具**
2. **加速**：时间压缩（如 1 交易日 = N 秒，可配），支持**多策略/多参数并行**（吃满多核；GPU 可用则用）
3. **能测试量化代码**：提供**标准策略接口** —— 新策略只需实现约定方法即可接入，无需改引擎
4. **24 小时运行**：开机自启、断点续跑、崩溃自恢复、日志轮转、**健康检查**；有最小化的查看入口（浏览器打开即用）
5. **资源硬上限**（老板一贯要求，超了算不合格）：
   - 项目目录总量 **≤4GB**，模拟产出（saves/等）**≤2GB**（超出用滚动归档 + 检查点覆盖）
   - 进程 RSS **≤512MB**（node/python 堆显式锁上限）
6. **不许重启 Win、不许改电源/引导、不许动老板在用的驱动和脚本**

### 交付物 3：完整量化测试报告 + 真实股市场景收益率

必须包含：

- 每个策略在各市场情形（牛/熊/震荡）下的：**年化收益、夏普、最大回撤、胜率、盈亏比、换手率、成本占比**
- **样本外结果单独列出**（调参用的时间段不许算进成绩）
- **策略失效条件**（什么市场环境下会亏，亏多少）
- **与基准对比**（买入持有 / 等权 / 指数）
- 报告可复现：给出**一条命令**让别人能重跑出同样的表

### ⚠️ 关于"我需要这套代码能做到在真实场景下盈利"——诚实条款（不可协商）

**任何人在事前都无法保证盈利。** 本项目的验收标准是**可验证的工程与证据**，不是把曲线画好看：

- ✅ 验收：系统无未来函数、含全部现实成本、在样本外与多种市场情形下给出**真实数字**（包括亏损区间）、报告如实写明策略失效条件
- ❌ 不合格：为了"看起来赚钱"而挑样本、调参数、隐掉成本、隐掉亏损段、用未来信息
- **如果结果不赚钱，报告必须如实呈现。编造或粉饰一律视为任务失败。**（老板原则："版本号诚实"）
